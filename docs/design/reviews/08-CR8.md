# CR8 代码审查（2026-11-06）

范围：D3a 一致性检查（`core/consistency.py`、elle-cli 的准入与 CI 步骤，PR #52）。合入后审查，修复单独开 PR。

## 结论

确认 3 条缺陷，都会让检查器在历史上崩溃（elle-cli 退出码 255、一段 Java 调用栈），用例报"检查器没有结果"，而不是给出一致 / 不一致的结论；另有 1 处加固。每条都有测试（`test/testconsistency/test_consistency.py::TestCr8`，修复前全部失败）。

| # | 问题 | 后果 | 修复 |
|---|---|---|---|
| 1 | 操作抛出的不是 `Exception` 而是 `BaseException`（`pytest.skip()` / `fail()`、`KeyboardInterrupt`）时，没有记完成 | 这个进程留着一个未完成的 invoke，它的下一个操作又开一个，Knossos 在这样的历史上崩溃 | `BaseException` 同样记为 `info`，换新的进程号，再抛出 |
| 2 | 操作名直接写成 EDN 关键字，不检查 | `call('add one', ...)` 写出 `:add one`，检查器解析失败崩溃 | `K()` 只接受 EDN 能读回的名字；`call()` 在执行操作之前就拒绝 |
| 3 | 浮点数 NaN、无穷大照样写进历史 | 检查器做算术时崩溃 | 写历史时拒绝非有限数；`call()` 在执行之前检查操作的值 |

**加固**：jar 的哈希核对按路径缓存，同一进程里文件被替换后不会再核对。改为按路径、大小和修改时间缓存。

**核实后没有问题**：事务模型（list-append）的反例格式：elle-cli 的 JSON 里是 `anomaly-types`、`not`，报告写成"异常：G1c；不满足 read-committed"。
