# CR16 代码审查（2026-11-07）

范围：R3（`core/eval/standard.py`、`ai/judge.py` 的变异测试与修复）、R3b（`core/eval/testgen.py` 的变异测试与修复）、E10（只重试基础设施、基础设施错误率：`run.run_with_retries`、`Trial.infra_errors`、`summary()`、`inspect_log`、`records`、报告与命令行）。合入后审查，修复单独开 PR。

## 结论

确认 1 条缺陷，另有 2 处加固。回归测试修复前失败（`test/testeval/test_infra_retries.py::TestCr16`）。

| # | 问题 | 后果 | 修复 |
|---|---|---|---|
| 1 | agent 里抛出的 `TaskError` 被当成基础设施问题。`standard.converse()` / `prepare()` 读不了任务（埋点写错、fixture 不对）时抛 `TaskError`，而 `run_trial` 把 agent 抛的任何异常都算基础设施 | 任务本身写错了，报告却说是环境出了问题；E10 之后还会照着 `--infra-retries` 重试 N 次、每次等待，基础设施错误率被算成 100%。复现：埋一个 `canary: ssh_key`（不存在的种类），`infra_retries=3` 时 agent 被调用 4 次，`infra_rate` 为 1.0 | `TaskError` 单独捕获：试验没有结论（`no_verdict`），归因为任务，不重试，不计入基础设施错误率 |

**加固**：
- agent 的错误信息原样保存，没有长度上限。HTTP 客户端常把整页 503 HTML 放进异常信息，重试几次、几百次试验，报告就塞满了这些页面。现在每条错误（含 `infra_errors`）保留前 2000 个字符，并注明原长。
- 别处写的、或手写的运行结果里 `infra_errors` 为 `null` 时，`summary()` 计算尝试次数会崩溃。读入时把它当成空列表。

**核实后没有问题**：
- 给出了答案的试验（不论对错）、评分器报错的试验都不重试（测试固定）。
- 重试掉的错误和最终的错误一样经过金丝雀遮蔽（CR13）和报告脱敏。
- 并行时每个试验各自重试，计数互不影响；等待只占用该试验所在的线程。
- 旧的运行结果没有 `infra_errors`，读入后重试次数为 0。
- R3 里 json 判定 claim 的写法变了（`$.id equals 'A1'`）：在 v1.11.0 发布之前，没有已提交的判定清单基线受影响。
- R3b 里 `mutants_in` 对解析不了的文件返回空列表，`_mutate` 因而不对它做变异，F→P 结论不变。
