# CR2 代码审查（2026-11-06）

范围：A1（接口身份与登录提供者）、L1（分层用例库）、A3（Web 登录态 `page_as`）。依据：[决策 14](../decisions/14-技术方案与实施计划.md) 的审查节点。A3 的 PR 合入前审查，问题和修复放在同一个 PR 里。

## 结论

共 22 条。以下按后果分组，都已修复，每条有测试（标"补测试"的是审查指出缺测试的能力）。

## 会让结论出错

| # | 问题 | 修复 |
|---|---|---|
| 1 | 接口登录拿到的 cookie 放进浏览器时去掉了域名前的点。Playwright 把不带点的域名当作只对本主机有效，`Domain=shop.example` 的 cookie 到不了 `www.shop.example`，页面被跳回登录页，最后报"测试数据"问题 | 保留前导点 |
| 2 | 请求没有 Content-Type 时，会话的默认请求头覆盖用例自己写的请求头：`Accept: text/csv` 发出去成了 `*/*`。早于本轮就存在 | 会话请求头只补缺，不覆盖 |
| 3 | 查询参数形式的凭据（`ApiKey(param=...)`）遇到列表或字符串形式的 `params` 时被悄悄跳过，请求未认证，重放同样未认证，最后算成产品缺陷 | 三种形式都加上 |
| 4 | `login_url` 当作不锚定的正则匹配整个 URL：`/account/login-history`、`?next=/login` 都被当成登录页 | 只对路径做完整匹配 |
| 5 | 单页应用在页面加载完之后由脚本跳去登录页，检查时还没跳 | 声明了 `login_url` 时，先等页面空闲（最多 3 秒）再检查 |
| 6 | `web_headers` 用 `set_extra_http_headers` 替换掉了用例自己在 `browser_context_args` 里设的请求头 | 合并 |
| 7 | 判断"凭据能不能进浏览器"靠的是 `web_prepare` 有没有被重写：只为设置地理位置而重写它的提供者，带着请求头凭据打开的是未登录的页面 | `web_prepare` 返回 True 才算交付了凭据 |

## 凭据外泄

| # | 问题 | 修复 |
|---|---|---|
| 8 | 页面登录用的上下文由 pytest-playwright 的 `new_context` 创建，会被录制 trace。用例失败时保留的 trace 里有输入的口令 | 页面登录用 `browser.new_context` 创建，不录制 |

## 崩溃与误导

| # | 问题 | 修复 |
|---|---|---|
| 9 | 用例的 `browser_context_args` 已经带 `storage_state` 时，页面登录报 `TypeError` | 给出明确的错误 |
| 10 | 手册让人在 `login()` 里驱动浏览器，而 pytest-playwright 已经在同一线程里运行，再起一个 Playwright 会失败 | 改为 `web.share_with_api(name, page)`：用 `page_as` 登录后把浏览器的登录交给接口侧；手册同步修改 |
| 11 | `forget()` 删掉了缓存条目，版本号从 1 重新开始；拿着旧版本号来续期的线程会再登录一次，单会话的服务上会把刚拿到的登录顶掉 | 只把条目标为过期，版本号继续累加 |
| 12 | `web.trace` 写错（`retain_on_failure`）时，pytest 报用法错误，运行器只能说"检查选择器" | 读取时校验并点名配置项 |
| 13 | cookie 的值是数字时 Playwright 拒收 | 转成文本 |
| 14 | `HTTPOnly` 这类大小写写法识别不出来 | 不区分大小写 |
| 15 | `localhost.local`（cookiejar 对无点主机名的叫法）在没有 `base_url` 时原样保留，浏览器不会发送；真实的 `*.local` 主机反而被改成网站的主机名 | 只把无点主机名还原成它自己 |
| 16 | `browser_cookies` 报错时，刚建的浏览器上下文没有关闭 | 先算 cookie 再建上下文，出错时关闭 |
