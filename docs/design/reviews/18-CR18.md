# CR18 代码审查（2026-11-07）

范围：F→P 的 SWT-bench 口径（`testgen.grade(discard_out_of_scope=, weak_rule=)`、`ipandora eval f2p --keep-out-of-scope --no-weak-rule`，#87）。合入后审查，修复单独开 PR。

## 结论

确认 1 条缺陷。回归测试修复前失败（`test/testeval/test_testgen_plain.py::TestCr18`）。

| # | 问题 | 后果 | 修复 |
|---|---|---|---|
| 1 | 关掉弱复现规则后，只要 agent 的测试文件里有一个收集失败，所有测试文件里收集到的测试都记为"修复前失败"。`_selected` 遇到收集错误时返回全部文件，不区分是哪个文件出的错 | agent 新加了 `tests/test_mul.py`（导入修复才加的函数，收集失败），又在已有的 `tests/test_existing.py` 里加了一个本来就能过的测试：后者被记成复现了 bug；`test_existing.py` 里 agent 没碰过的老测试也被当成它的测试判分，修复后要是其中一个挂了，算 agent 没过 | 只有收集失败的那些文件，按 SWT-bench 的算法把修复后收集到的测试都记为修复前失败；agent 的其他文件照常挑出新增或改动的测试，在修复前实际跑一遍再判 |

**核实后没有问题**：
- 两条规则默认都打开，`f2p-selfcheck` 总是用默认口径；F→P 的 claim 不变，记录、失败原因、`eval table` 照常工作，判定名和 `rules` 写明用了什么口径。
- 保留越界改动时，agent 改到修复补丁那几行会让补丁打不上，判为出错，和官方 harness 一致。
- 关掉弱复现规则后，修复前在执行阶段失败的任何异常都算复现，跳过的测试仍算通过。
