# CR13 代码审查（2026-11-07）

范围：E5a 标准评分器（`core/eval/standard.py`、数据集的 fixture 与哈希、`spec` 不写 `grade()` 的默认评分器、`selfcheck` 的 `task` 类别）和 E5b 埋点与安全判定（`prepare()` / `converse()`、`AgentResult.setup`、试验记录里的金丝雀遮盖）。合入后审查，修复单独开 PR。

## 结论

确认 3 条缺陷，都在 E5b。每条都有测试（`test/testeval/test_standard_safety.py::TestCr13`，修复前全部失败）。

| # | 问题 | 后果 | 修复 |
|---|---|---|---|
| 1 | 外联白名单（`egress_allow`）用的 `EgressGuard` 是进程级的：并行（`workers>1`）时两次试验的守卫同时打开，任何一次外联都记到每个守卫头上 | 一次什么都没连的试验，因为同时运行的另一次试验连了外网，被判"有白名单之外的外联"而失败。文档写了要 `workers=1`，但没有任何东西拦着 | `prepare()` 打开守卫前发现已有别的守卫，就拒绝开始，报"需要 `workers=1`"：这次试验算基础设施问题，而不是被错判 |
| 2 | agent 在 `converse()` 里抛异常时，试验记为基础设施问题，异常消息原样写进记录；遮盖只在评分之后做，这条路径不经过评分 | agent 报错时引用了它拿到的金丝雀（"cannot use sk-canary-…"），这个值进了试验记录和报告 | `Setup` 退出时，若有异常，先把异常参数里的金丝雀（含 base64、hex）换掉再抛出 |
| 3 | `initial_state()` 只看有没有 `plant` 键，评分器看 `plant` 是否非空 | `plant: []` 的任务在 `prepare()` 之外构造世界就报错，而评分器把它当作没有埋点：两处说法不一 | 统一按"非空才算有埋点" |

**核实后没有问题**：
- 参考解在同样埋好点的世界上重放，金丝雀每次重新生成；`selfcheck` 输出里的判定在评分器返回前已遮盖。
- 终态的起点：`converse()` 记下 agent 开始时 world 的样子，没有埋点、没有 fixture 的题照样按 E5a 的方式判。
- 拼错的 `expected` 键、判定里多余的键、埋了没判和判了没埋，都报 `TaskError` 并归为"任务有问题"；`eval selfcheck` 以退出码 1 报出。
- 只有 `selfcheck` 交来的参考解（`is_reference`）会被重放，agent 输出的列表不会被当成工具调用执行。
