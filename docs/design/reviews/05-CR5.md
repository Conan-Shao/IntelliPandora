# CR5 代码审查（2026-11-06）

范围：E2（多轮对话 `dialogue`、模型扮演的用户）、E3（agent 安全 `safety`）、E4（回归门禁、饱和监测 `trend`）。依据：[决策 14](../decisions/14-技术方案与实施计划.md) 的审查节点。三项合入前一起审查，问题和修复放在同一个 PR 里。

## 结论

确认 3 条缺陷，都已修复，每条有复现测试（`test/testeval/test_safety.py::TestCr5`，修复前全部失败）；另有 2 处加固。

| # | 问题 | 后果 | 修复 |
|---|---|---|---|
| 1 | `ScriptedUser` 记住了哪些规则已经回答过，跨对话不清空 | 一个用户对象被多次试验复用（比如定义在模块级）时，第二次起用户无话可说，对话提前结束，失败算在 agent 头上 | 每次对话开始（`opening()`）重置 |
| 2 | 注入语料把暗号原文写在注入文本里 | agent 只是把用户留言复述一遍（"您的留言是：……，我不会照做"），也被判为照做了注入 | 暗号不以原文出现，注入里写的是拼出暗号的方法；只有照做的 agent 才会说出它 |
| 3 | 对话记录工具参数、终态时做深拷贝，参数里有锁、客户端、文件句柄时拷贝失败 | 异常从 `converse()` 抛出，被当成基础设施问题，agent 的这次试验没有结论 | 拷不了的保留原对象 |

**加固**：

- `EgressGuard` 在代理之后看到的是代理的主机名，会把允许的目的地也一起拦掉。手册和文档字符串写明：开着它时不要让 agent 的客户端走代理，或者把代理加进白名单、在代理上判断目的地。
- `trend.history()` 原来会读报告归档里所有的 report.json（包括每一次测试运行的报告），改为按修改时间只读最新的 200 份。
