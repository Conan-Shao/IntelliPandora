## 结论

共 120 余条，按后果分级：

- **P0**：14 条。会让结论出错（误报或漏报"变弱/变差"、基线被清空），或者让凭据离开本机。
- **P1**：约 30 条。崩溃、数据丢失、并行与串行不一致。
- **P2**：约 40 条。门禁有缺口、文档和代码不一致、边界不严。
- **P3**：重复实现、死代码，修到哪一块顺手清。

最要紧的是第一条：**`ipandora run login --fail-on-weakened` 这种带 `-k` 选择器的运行，会把所有没选中的用例报成"判定被削弱"；如果再带 `--update-baseline`，还会把它们在基线里改成"被排除"，以后删掉断言也查不出来。** 判定清单是这个框架防止 agent 偷偷改弱用例的核心机制，这条要最先修。

## P1：崩溃、数据丢失、并行不一致

**运行器**

- 嵌套调用 `run()` 时，退出会撤销外层会话对 `raises`/`warns` 的补丁，并卸载 Web 插件。
- `RunResult.to_dict` 丢了 coverage。
- 标了 skip 的用例没有 index/dims：xdist 下顺序不确定，并行和串行的判定清单不一致。
- `Runtime.Option.env` 串行和并行取值不同。
- 环境变量、`__pycache__` 的改动发生在 try/finally 之前，出错时不恢复。
- `concurrently` 超时后线程还在往证据里写。
- `Results.warning` 在空序列上 `max()` 崩溃。
- `web.remember` 的 OSError 让 `run()` 直接抛出；`web.remember` 并发写有竞争。
- 锁目录依赖 `IPANDORA_RUNS_DIR`，两个设置不同的进程互相看不到锁。
- 断言放宽后的配对，在同一主语有多条判定时会配错。

**报告**

- `hljson` 遇到非字符串的 body 抛 TypeError，整份报告生成失败（已复现）。
- 历史归档 `_prune` 在 run_id 为空串时 rmtree 整个归档目录（已复现）。
- `gate_weakened` 既没传给模板，也没序列化：报告看不出这次是否因为削弱而失败（已复现）。
- 空运行时报告写"退出码 1"，CLI 实际退出 0。
- 通过率说明文字把 ERROR 排除在外：9 个 error 时显示 100%。
- JUnit 遇到未知状态时计数不对。

**判定库、证据、Web**

- 视觉判定的 `_slug` 把非 ASCII 名字都变成同一个名字，中文金标准互相覆盖（已复现）。
- 附件文件名截断后可能碰撞。
- `_ARIA` 正则漏掉带 `[level=1]`、`[checked]` 的行（已复现）。
- recorder 嵌套 begin/end 时，外层证据丢失。
- 被捕获的定位异常留下的"定位过期"标记，覆盖后来的真实失败归因。
- `matches_golden` 在金标准缺失等情况下直接抛异常，不返回 Check。
- `CHECK_LINE` 不匹配表达式为空的行（已复现）。
- `json_body` 不处理 BOM。
- jsonpath 分词有误，部分路径取错值（已复现）。
- `_to_decimal` 接受 `'1_000'`（已复现）。
- 两个 `APIResponse` 的判定描述会撞名。

**评测**

- 输出不能 deepcopy 时，`Trial.to_dict` 崩溃（已复现）。
- spec 模块不在 `sys.modules` 里时，其中的 dataclass 会出错（已复现）。
- spec 不是 `.py` 时报 AttributeError（已复现）。
- 数据集文件不存在、YAML 写错，直接抛 traceback。
- `agreement` 把字符串 `'false'` 当成 true（`bool('false')`）。
- id 为 `0` 的任务被拒。

**命令行和模板**

- Windows 下目标目录和当前目录不在同一个盘时，`init` 的 `relpath` 崩溃。
- 生成的 conftest 只改了大写的 `NO_PROXY`：设置了小写 `no_proxy` 的机器上，示例请求走代理失败；而且改动不恢复。

## P2：门禁缺口、文档与代码不一致

**评测，行为和文档不符**

[guide/eval.md](../../guide/eval.md) 有好几处写了，但代码没做到：

- `eval run` 永远退出 0：和基线比是"变差"，CI 也是绿的。其他命令都把结论映射成退出码。
- 显式给的 `--baseline` 文件不存在时，悄悄当作"没有基线"。`ipandora run` 在这种情况下会警告。
- 文档说"报告按极性分开看"，代码没分。
- `budget` 写了，但没有执行。
- 参考解文件不存在时，被当成直接写的值。
- CLI 和模板把自检的三类问题都写成"参考解判不过"。
- 参考解缺失时 `selfcheck` 退出 1，可这不是"判不过"。
- `mean_score` 漏算只有可选判定的试验。
- 不可比时，`eval.html` 仍然显示各标签的结论。
- 任务 id 重复时没有报错。
- `--partial` 的说明有歧义。

**门禁脚本**

- `check_docs.py` 不展开嵌套子命令：`docs/reference/cli.md` 里 `ipandora eval` 只有一行 `eval_action`，`run`/`selfcheck`/`samples`/`agreement` 和它们的参数都没有，门禁却是通过的（已在生成文件里看到）。
- `check_docs.py` 的配置参考漏掉顶层标量；列表型的值显示成 `null`。
- `check_components.py` 按 action 名字去重：两个 workflow 把同一个 action 固定到不同 SHA 时，只核对其中一个。
- `security_report.py`：许可证一栏只看锁文件里的包，阻断判断看的是全部包，于是报告写"通过"，作业却失败。
- `security_report.py`：两个锁文件包含哪些可选组，报告里的描述和 `update_locks.py` 实际的不一致。
- `update_locks.py --cutoff` 只给日期时，会把当天下午发布、不满 14 天的版本放进锁文件。
- `mutation.py` 依赖的 mutmut 没登记、没锁定。
- `mutation.py` 给包路径猜测试目录时猜错。
- `mutation.py` 匹配 `[mutmut]` 段失败时，悄悄变异整个 `src/`。
- `check_packaging.py` 会删掉工作区里的 `src/*.egg-info` 和 `build/`。

**模板**

- 生成的 `.gitignore` 不忽略 `conf/<env>.yaml`，可生成的 AGENTS.md 让人把凭据放在那里。
- 项目模板里 workflow 固定的 action SHA，不在 `check_components` 和 Dependabot 的覆盖范围内。

**其他**

- 只要有 deselected 用例，`run` 就说"N 条被 --exclude-flaky 排除"，哪怕根本没用这个参数。
- 历史索引里的通过率算法和报告里的不一致。
- 历史的"新失败"不区分选择器和环境。
- `to_curl` 把 dict 类型的 body 输出成 Python repr。
